`ck ecs` works on Amazon ECS in the terminal's AWS profile and region. Start a session with [`ck aws login`](/commands/aws/#ck-aws-login) first.

| Command | Purpose | Effect |
|---|---|---|
| [`clusters`](#ck-ecs-clusters) | List clusters | Read-only |
| [`services`](#ck-ecs-services) | List services in a cluster | Read-only |
| [`tasks`](#ck-ecs-tasks) | List tasks in a cluster | Read-only |
| [`service-tasks`](#ck-ecs-service-tasks) | List tasks of one service | Read-only |
| [`task-info`](#ck-ecs-task-info) | Show details of one task | Read-only |
| [`describe`](#ck-ecs-describe) | Summarize a service | Read-only |
| [`exec`](#ck-ecs-exec) | Run a command in a container | Interactive |
| [`exec-running`](#ck-ecs-exec-running) | Run a command in the first running task | Interactive |
| [`logs`](#ck-ecs-logs) | Show a task's first container | Read-only |
| [`stop`](#ck-ecs-stop) | Stop a task | Interrupts workloads |

Clusters, services and tasks are identified by **name** or **ID** (the last part of the ARN); full ARNs also work wherever the AWS CLI accepts them. The task ID is shown by `tasks` and `service-tasks`.

## ck ecs clusters

List cluster names.

<CommandFacts effect="read" runs="aws ecs list-clusters" needs="AWS session, aws; ecs:ListClusters" />

```text
ck ecs clusters
```

```text title="Output (illustrative)"
my-cluster
batch-cluster
```

## ck ecs services

List the service names in a cluster.

<CommandFacts effect="read" runs="aws ecs list-services --cluster <cluster>" needs="AWS session, aws; ecs:ListServices" />

```text
ck ecs services <cluster>
```

| Argument | Description |
|---|---|
| `cluster` | Required. Cluster name or ARN. |

```bash
ck ecs services my-cluster
```

## ck ecs tasks

List the tasks in a cluster with their status, first container and uptime.

<CommandFacts effect="read" runs={['aws ecs list-tasks', 'aws ecs describe-tasks']} needs="AWS session, aws, jq; ecs:ListTasks, ecs:DescribeTasks" />

```text
ck ecs tasks <cluster> [--running]
```

| Argument | Description |
|---|---|
| `cluster` | Required. Cluster name or ARN. |
| `--running` | Optional. Passes `--desired-status RUNNING`. Must come right after the cluster name. |

```bash
ck ecs tasks my-cluster --running
```

```text title="Output (illustrative)"
TASK ID                                  LAST STATUS     DESIRED STATUS  CONTAINER                 UPTIME
==============================================================================================================
0123456789abcdef0123456789abcdef         RUNNING         RUNNING         app                       2d 4h
fedcba9876543210fedcba9876543210         RUNNING         RUNNING         app                       35m
```

- **CONTAINER** is the task's first container only. Use [`task-info`](#ck-ecs-task-info) or the AWS console to see sidecars.
- **UPTIME** is the time since the task was created.
- `ListTasks` already returns only tasks with desired status `RUNNING` by default, so the output is the same with or without `--running`. Tasks that are shutting down or recently stopped are not listed; query them with `aws ecs list-tasks --desired-status STOPPED`.
- With no tasks, prints `No tasks found in cluster: <cluster>` and returns `0`.

<Aside type="caution">
`aws ecs describe-tasks` accepts at most 100 tasks per call, and CloudKit sends all of them at once. In clusters with more than 100 matching tasks, the command fails with an AWS validation error. Use [`service-tasks`](#ck-ecs-service-tasks) to narrow the list.
</Aside>

## ck ecs service-tasks

Same as [`tasks`](#ck-ecs-tasks), limited to one service.

<CommandFacts effect="read" runs={['aws ecs list-tasks --service-name <service>', 'aws ecs describe-tasks']} needs="AWS session, aws, jq; ecs:ListTasks, ecs:DescribeTasks" />

```text
ck ecs service-tasks <cluster> <service> [--running]
```

| Argument | Description |
|---|---|
| `cluster` | Required. Cluster name or ARN. |
| `service` | Required. Service name. |
| `--running` | Optional. Must come right after the service name. |

```bash
ck ecs service-tasks my-cluster my-service --running
```

With no tasks, prints `No tasks found for service: <service>` and returns `0`.

## ck ecs task-info

Show the details of one task: status, first container, image, uptime and creation time.

<CommandFacts effect="read" runs="aws ecs describe-tasks --tasks <task-id>" needs="AWS session, aws, jq; ecs:DescribeTasks" />

```text
ck ecs task-info <cluster> <task-id>
```

| Argument | Description |
|---|---|
| `cluster` | Required. Cluster name or ARN. |
| `task-id` | Required. Task ID or ARN. |

```bash
ck ecs task-info my-cluster 0123456789abcdef0123456789abcdef
```

```text title="Output (illustrative)"
Task ID: 0123456789abcdef0123456789abcdef
Last Status: RUNNING
Desired Status: RUNNING
Container: app
Image: 111111111111.dkr.ecr.eu-west-1.amazonaws.com/app:1.4.2
Uptime: 2d 4h
Created At: 2026-10-19T08:12:44.120000+00:00
```

If the task does not exist (for example, it stopped long ago), `jq` reports an error because the response contains no task.

## ck ecs describe

Summarize a service: name, status, running and desired task counts, and task definition.

<CommandFacts effect="read" runs="aws ecs describe-services" needs="AWS session, aws; ecs:DescribeServices" />

```text
ck ecs describe <cluster> <service>
```

```bash
ck ecs describe my-cluster my-service
```

Prints an AWS CLI table with five values, in order: service name, status (`ACTIVE`, `DRAINING` or `INACTIVE`), running task count, desired task count, and task definition ARN. A running count below the desired count usually means tasks are failing to start; check stopped tasks in the console or with `aws ecs list-tasks --desired-status STOPPED`.

## ck ecs exec

Run a command, or open a shell, inside a running container using ECS Exec.

<CommandFacts
	effect="session"
	runs="aws ecs execute-command --interactive"
	needs="AWS session, aws, Session Manager plugin, ECS Exec enabled on the task; ecs:ExecuteCommand"
/>

```text
ck ecs exec <cluster> <task-id> <container> [command...]
```

| Argument | Description |
|---|---|
| `cluster` | Required. Cluster name or ARN. |
| `task-id` | Required. Task ID or ARN. |
| `container` | Required. Container name as defined in the task definition. |
| `command` | Optional. Everything after the container name, joined with spaces. Default: `/bin/bash`. |

```bash
ck ecs exec my-cluster 0123456789abcdef0123456789abcdef app                # bash shell
ck ecs exec my-cluster 0123456789abcdef0123456789abcdef app sh             # images without bash
ck ecs exec my-cluster 0123456789abcdef0123456789abcdef app ls -la /var/log
```

ECS Exec runs the command without a shell, so pipes, redirects and `&&` are not interpreted. Wrap them in a shell explicitly:

```bash
ck ecs exec my-cluster 0123456789abcdef0123456789abcdef app sh -c "'env | sort'"
```

CloudKit joins the words with spaces, so this passes `--command "sh -c 'env | sort'"` to the AWS CLI. The inner quotes keep `env | sort` together as the argument to `sh -c`.

<Aside type="note" title="ECS Exec prerequisites">
The service or task must have been started with `enableExecuteCommand` turned on, the **task role** needs the `ssmmessages:*Channel` permissions, and the container image must contain the command you run (many minimal images have no `/bin/bash`). See [Run commands in ECS containers](/guides/ecs/#prerequisites-for-ecs-exec).
</Aside>

## ck ecs exec-running

Like [`exec`](#ck-ecs-exec), but picks a running task for you: useful when any replica will do.

<CommandFacts
	effect="session"
	runs={['aws ecs list-tasks --desired-status RUNNING', 'aws ecs execute-command --interactive']}
	needs="AWS session, aws, Session Manager plugin, ECS Exec enabled; ecs:ListTasks, ecs:ExecuteCommand"
/>

```text
ck ecs exec-running <cluster> <container> [--service <service>] [command...]
```

| Argument | Description |
|---|---|
| `cluster` | Required. Cluster name or ARN. |
| `container` | Required. Container name. |
| `--service <service>` | Optional. Only consider this service's tasks. Must come right after the container name. |
| `command` | Optional. Default: `/bin/bash`. |

```bash
ck ecs exec-running my-cluster app
ck ecs exec-running my-cluster app --service my-service php artisan about
```

The task is the **first** one returned by `aws ecs list-tasks`; it is not chosen by age, health or load. Without `--service`, it can be a task of any service, so the container name must exist in that task. With no running task, prints `No running tasks found …` and returns `0`.

## ck ecs logs

Print a task's ID and first container name.

<CommandFacts effect="read" runs="aws ecs describe-tasks" needs="AWS session, aws, jq; ecs:DescribeTasks" />

```text
ck ecs logs <cluster> <task-id> [--tail N]
```

```text title="Output (illustrative)"
Task: 0123456789abcdef0123456789abcdef
Container: app
Note: Configure CloudWatch logging in your task definition to view logs here
```

<Aside type="caution" title="Does not fetch logs">
Despite its name, this command does not read any log lines, and `--tail` is accepted but ignored. To read logs of a task that uses the `awslogs` driver, use the AWS CLI directly, for example `aws logs tail <log-group> --follow`. The log group is in the task definition's `logConfiguration`.
</Aside>

## ck ecs stop

Stop a task.

<CommandFacts effect="disrupt" runs="aws ecs stop-task" needs="AWS session, aws; ecs:StopTask" />

```text
ck ecs stop <cluster> <task-id> [reason]
```

| Argument | Description |
|---|---|
| `cluster` | Required. Cluster name or ARN. |
| `task-id` | Required. Task ID or ARN. |
| `reason` | Optional. Recorded on the stopped task. Default: `Stopped via CLI`. Quote it if it contains spaces. |

```bash
ck ecs stop my-cluster 0123456789abcdef0123456789abcdef "stuck worker"
```

Prints a table with the task ARN and its last status.

<Aside type="danger" title="No confirmation">
The task stops immediately and in-flight requests are interrupted. If the task belongs to a service, ECS starts a replacement to meet the desired count; a standalone task is gone for good.
</Aside>
